# 06 分布式训练

[返回首页](../README.md) · [题目索引](question-bank.md)

## 核心知识

先区分四类显存：权重、梯度、优化器状态、中间激活，另计临时缓冲、通信桶与碎片。模型能加载不代表能训练，也不代表能承载目标推理并发。

| 策略 | 切分对象 | 常见代价 |
| --- | --- | --- |
| 数据并行 DP | 各副本处理不同样本 | 梯度同步，模型状态重复 |
| 张量并行 TP | 单层矩阵计算 | 层内频繁通信，依赖互联带宽 |
| 流水线并行 PP | 不同层 | 流水线气泡与调度复杂度 |
| 专家并行 EP | MoE 专家 | token 分发、负载不均和 all-to-all |
| 状态分片 | 参数、梯度、优化器状态 | 按需聚合与通信内存 |

这些策略可组合，具体收益应由模型结构、互联和负载决定。

## 常见面试题

<a id="d01"></a>
### D01｜如何估算全参数训练的模型状态显存？【P0】

**回答要点：** 一种混合精度 Adam 配置含：低精度权重 2 bytes、低精度梯度 2 bytes、FP32 主权重 4 bytes、FP32 一二阶矩 8 bytes，共约 16 bytes/参数。7B 参数约 112 GB，即约 104.3 GiB，仅为这些状态的合计，不含激活与其他缓冲。实际梯度精度、主权重、优化器和分片实现会改变该值。

**追问：** 为什么不能直接除以 GPU 数得到每卡峰值？分片不一定覆盖全部对象，参数聚合、激活、临时副本、负载不均和通信桶都会影响峰值。

<a id="d02"></a>
### D02｜什么时候选择 DP、TP、PP 或 EP？【P0】

**回答要点：** 模型可单卡容纳时先评估 DP；单层或单卡状态过大时考虑 TP 或状态分片；层数较深且适合分阶段时考虑 PP；MoE 的专家分布可使用 EP。TP 常放在互联较快的设备组内，跨节点通信应结合拓扑设计。不要把并行维度数越多视为越高效。

**追问：** PP 为什么有气泡？部分阶段在流水线填充、排空或前后向调度中等待；microbatch 数和调度会影响利用率、激活量与延迟。

<a id="d03"></a>
### D03｜ZeRO 的三个阶段分别切分什么？【P0】

**回答要点：** ZeRO-1 分片优化器状态，ZeRO-2 进一步分片梯度，ZeRO-3 再分片参数。减少数据并行副本间冗余的同时，引入参数聚合等通信；offload 是另一维度的存储转移，并不等同于某个分片阶段。见 [ZeRO 原论文](https://arxiv.org/abs/1910.02054)。

**追问：** ZeRO-3 总会更快吗？不保证。它主要扩大可训练规模，较小模型或慢互联上可能因通信和调度开销变慢。

<a id="d04"></a>
### D04｜梯度累积如何影响有效 batch 与损失归约？【P0】

**回答要点：** 等长、等大小 microbatch 下，有效样本 batch 为每卡 microbatch × 数据并行副本数 × 累积步数；不要把 TP/PP 卡数重复计入。变长样本更应跟踪有效 token。若每个 microbatch 都先算平均损失，再等权累积，会给短批次的每个 token 更大权重；按总有效 token 归一化才能对应目标的全局 token 平均。

**追问：** 裁剪和调度应何时进行？通常在一次完整累积后按一次 optimizer update 执行，混合精度下还要考虑反缩放；具体依据训练框架的归约方式。

<a id="d05"></a>
### D05｜GPU 利用率低但没有 OOM，如何定位瓶颈？【P1】

**回答要点：** 拆分数据读取、前向、反向、通信与优化器耗时，查看 trace 和各 rank 等待。检查数据加载、padding 浪费、过小 microbatch、算子碎片、同步点和通信重叠。报告有效 tokens/s、step 时间、峰值显存和固定硬件预算下的吞吐；GPU 利用率单值不足以说明效率。

**追问：** MFU 怎么解释？模型 FLOPs 利用率是估计的模型运算量除以硬件理论算力与时间，依赖 FLOPs 计数与精度口径，不应跨口径直接比较。

<a id="d06"></a>
### D06｜OOM 时如何按来源选择优化手段？【P0】

**回答要点：** 加载即 OOM 优先看权重与状态，前后向峰值 OOM 看激活、长序列和临时缓冲，optimizer step OOM 看状态初始化及更新缓冲。激活重计算用额外计算换显存；减少 microbatch、优化注意力、使用分片或 offload 分别对应不同来源。记录分配与保留显存，区分真实容量不足和碎片问题。

**追问：** 减小 batch 没效果可能为什么？主要开销可能来自常驻模型状态，而不是随 batch 变化的激活。

## 易错点

- 不说明状态精度与单位，直接背诵“每个参数占多少显存”。
- 把数据并行度等同于总 GPU 数。
- 只看平均 step 时间，忽略最慢 rank、通信等待与长序列尾部。
