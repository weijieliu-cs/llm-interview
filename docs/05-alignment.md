# 05 偏好对齐与推理能力

[返回首页](../README.md) · [题目索引](question-bank.md)

## 核心知识

偏好优化需要先定义“更好”：事实性、完成任务、表达偏好和格式约束可能冲突。要区分偏好数据、奖励模型、可验证奖励与最终任务评测。

一种常见正则化目标是：

$$
\max_\theta\ \mathbb E_{x,y\sim\pi_\theta}[r(x,y)]
-\beta\,\mathbb E_x[D_{\mathrm{KL}}(\pi_\theta(\cdot|x)\Vert\pi_{ref}(\cdot|x))].
$$

$\pi_\theta$ 为当前策略，$\pi_{ref}$ 为参考策略，$\beta>0$ 约束相对参考策略的偏移。具体算法对采样、KL 估计和损失归约的处理不同。

## 常见面试题

<a id="a01"></a>
### A01｜经典 RLHF 流程包含哪些阶段？【P0】

**回答要点：** 典型流程先用示范数据 SFT，再收集相同输入下的候选回答偏好，训练奖励模型，最后用强化学习优化策略并约束偏移。RLHF 是一类方法，不能与 PPO 直接画等号。奖励模型偏差、采样成本和多模型状态使流程较复杂。原始案例见 [InstructGPT 论文](https://arxiv.org/abs/2203.02155)。

**追问：** 人类偏好是否等同于事实正确？不等同。流畅、长答案或迎合表达可能被偏好，需要独立的事实及任务评测。

<a id="a02"></a>
### A02｜DPO 的损失为什么包含参考模型？【P0】

对偏好对 $(x,y_w,y_l)$，定义：

$$
\Delta=\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-
\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)},\qquad
\mathcal L_{DPO}=-\mathbb E[\log\sigma(\beta\Delta)].
$$

**回答要点：** DPO 在相应奖励与偏好建模假设下，把正则化奖励优化转为成对偏好损失。参考策略提供相对概率基准；训练时不必显式训练独立奖励模型或进行在线 rollout。原始目标使用响应的序列对数概率之和，padding 和 prompt 应正确屏蔽。见 [DPO 原论文](https://arxiv.org/abs/2305.18290)。

**追问：** DPO 一定优于 PPO 吗？不一定。静态偏好覆盖、分布偏移、长度偏差和可用奖励条件都会影响选择；$\beta$ 的效果也不能脱离算法目标直接类比学习率。

<a id="a03"></a>
### A03｜PPO 中旧策略、参考策略与价值模型分别做什么？【P1】

**回答要点：** 旧策略是采样及重要性比率的基准，参考策略常用于约束相对初始策略的偏移；二者角色不同。价值模型估计回报基线以构造优势。PPO 使用概率比率的裁剪目标控制更新幅度，但裁剪并不保证每步 KL 都严格小于某常数。见 [PPO 原论文](https://arxiv.org/abs/1707.06347)。

**追问：** 训练变贵主要贵在哪里？在线生成、奖励计算、价值估计和多个模型状态都带来成本，应按 token 预算、显存和采样吞吐分析。

<a id="a04"></a>
### A04｜GRPO 如何避免独立价值模型？【P1】

**回答要点：** 对同一问题采样一组回答，用组内奖励统计构造相对优势，例如 $A_i=(r_i-\bar r)/(\operatorname{std}(r)+\epsilon)$，再进行带重要性比率和约束的策略更新。原始 GRPO 不训练独立 critic，但仍需要多次生成、奖励计算、旧策略以及参考约束等成本。具体归约和 KL 项应以使用的版本为准。见 [DeepSeekMath](https://arxiv.org/html/2402.03300v3)。

**追问：** 全组奖励相同会怎样？相对优势接近零，组内区分信号不足；需要检查题目难度分布、奖励稀疏度和采样多样性。

<a id="a05"></a>
### A05｜推理时增加计算、强化学习和蒸馏是什么关系？【P1】

**回答要点：** 推理时可增加候选数量、搜索或验证；强化学习通过奖励信号改善策略；蒸馏用筛选后的教师样本或分布训练学生。三者可以组合，但更长输出或更多候选不保证正确，必须固定或报告推理预算。相关实践见 [DeepSeek-R1](https://arxiv.org/abs/2501.12948)。

**追问：** best-of-N 和 pass@N 是一回事吗？不是。前者需要选择器实际挑出一个答案，后者衡量多个候选中存在正确答案的可能性，可能依赖测试判定。

<a id="a06"></a>
### A06｜如何发现并缓解 reward hacking？【P0】

**回答要点：** 同时观察训练奖励与独立任务指标，抽查高奖励失败案例，检查长度、重复、格式投机和验证器漏洞。使用隐藏测试、交叉验证器、奖励分解和对抗样本；涉及代码执行时隔离环境并限制资源。奖励提升不能单独作为上线依据。

**追问：** 为什么可验证奖励仍会错？测试覆盖不足、解析器漏洞或答案泄漏都会让错误解被奖励，验证器本身也需要评测。

## 易错点

- 把 DPO 描述成对 chosen/rejected 标签做普通语言模型 SFT。
- 把 PPO 的旧策略与用于 KL 的参考策略混为同一个角色。
- 认为无 critic 就意味着训练成本很低，或长推理就等于可靠推理。
