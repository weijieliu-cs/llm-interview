## 一页项目卡片

下列内容是填写模板，不是已发生的项目成果。先准备 1 分钟概述，再准备可展开的实验和失败案例。

| 项目项 | 需要填写的事实 |
| --- | --- |
| 问题与用户 | 谁遇到了什么问题，原方案为什么不足 |
| 个人职责 | 自己设计、实现或验证了哪些部分 |
| 数据 | 来源、使用范围、规模、划分、更新与脱敏方式 |
| 基线 | 基座/提示词/检索链路、版本、指标与预算 |
| 关键改动 | 改动针对哪类错误，用什么证据支持 |
| 结果 | 指标口径、真实前后值、样本量、硬件和耗时 |
| 消融 | 去掉关键组件、固定预算或替代方案后的结果 |
| 失败 | 一例未解决问题、影响范围和后续验证 |
| 交付 | 代码、配置、运行步骤、监控或回滚方式 |

## 两个可实践的项目方向

**RAG 质量诊断：** 自选可公开文档，构造有答案、无答案和多证据问题；比较关键词、向量、混合检索与重排。保存候选和引用，按解析、召回、重排、生成归因。先完成离线实验，不要求接入外部付费服务。

**低资源微调：** 在资源允许时选择具体基座与公开数据，比较不训练、LoRA 和量化微调；固定验证集、模板和生成配置，记录有效 token、峰值显存、训练时长与通用能力回归。没有硬件时可提交完整实验设计，不能把设计写成已完成实测。

| 实验 | 改动 | 质量指标 | 延迟或时长 | 峰值显存/成本 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 基线 | 填实际配置 | 待测 | 待测 | 待测 | 待验证 |
| 实验 A | 仅改一个因素 | 待测 | 待测 | 待测 | 待验证 |
| 实验 B | 关键组件消融 | 待测 | 待测 | 待测 | 待验证 |

## 60 分钟模拟面试

| 时间 | 任务 | 可选题目 |
| --- | --- | --- |
| 0—5 分钟 | 项目概述与个人贡献 | [X06](10-system-design.md#x06) |
| 5—20 分钟 | 基础原理与推导 | [F01](01-fundamentals.md#f01)、[T01](02-transformer.md#t01)、[S03](04-finetuning.md#s03) |
| 20—35 分钟 | 手写代码和边界解释 | [代码练习](../examples/README.md) |
| 35—50 分钟 | 系统设计与资源取舍 | [X01](10-system-design.md#x01) 或 [X03](10-system-design.md#x03) |
| 50—60 分钟 | 失败案例、追问与复盘 | [X04](10-system-design.md#x04)、[X05](10-system-design.md#x05) |

每部分按 0—3 自评：0 为无法作答；1 为能说概念；2 为能解释公式与条件；3 为能联系实验和取舍。将卡住的问题回链到对应知识点，下一轮优先验证这些薄弱项。

## 面经记录模板

记录自己的真实面试或有公开来源的面经，保留原始问题与个人解释的区别。汇总时按知识点去重，不凭一次记录推断“必考”或频率。

| 字段 | 内容 |
| --- | --- |
| 来源 | 原文链接或本人复盘；标明转载、待核实等状态 |
| 时间 | 面试/发布时间；缺失写未注明，并记访问日期 |
| 岗位与轮次 | 训练/应用/Infra；公司和轮次仅填已知信息 |
| 问题概括 | 用自己的话概括，避免复制整篇原文 |
| 知识点与题号 | 如 GQA → T04，KV Cache → I02 |
| 当时回答与追问 | 记录事实，不补写不存在的问答 |
| 待补知识 | 对应资料与验证方法 |

收录规则见 [参考项目说明](reference-projects.md)。
