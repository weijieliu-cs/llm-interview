# 04 SFT 与参数高效微调

[返回首页](../README.md) · [题目索引](question-bank.md)

## 核心知识

先确定要改变什么：持续预训练通常用于适应领域分布，SFT 用示例教授任务行为，偏好优化用比较或奖励信号调整输出。知识更新与行为学习也可以结合检索解决，不能由工具名称替代需求分析。

对响应 token 集合 $\mathcal A$，常见 SFT 目标为：

$$
\mathcal L_{\mathrm{SFT}}=-\frac{1}{|\mathcal A|}\sum_{t\in\mathcal A}\log p_\theta(x_t\mid x_{<t}).
$$

这是只计算 assistant 响应损失的一种常用策略，不是所有训练任务的固定要求。多轮对话要明确哪些轮次和工具结果参与监督。

## 常见面试题

<a id="s01"></a>
### S01｜持续预训练、SFT 和偏好优化如何选择？【P0】

**回答要点：** 若领域文本分布差异较大且有充足语料，可评估持续预训练；若需要稳定格式、任务流程或指令遵循，用高质量输入输出样本做 SFT；若候选答案已能生成但偏好排序不理想，可考虑偏好优化。先用提示词和小规模评测建立基线，再证明训练确有收益。

**追问：** 微调是否可靠地写入所有新事实？不保证。频繁更新、需出处和需权限控制的知识更适合检索链路，参见 [RAG R01](08-rag-and-agents.md#r01)。

<a id="s02"></a>
### S02｜SFT 的 loss mask、padding 和 packing 容易出什么错？【P0】

**回答要点：** 将无需监督的位置设为损失忽略标签，通常不等于从注意力中隐藏这些输入。padding 的注意力掩码与损失掩码要分别处理。packing 拼接多个样本时，要明确是否允许跨样本注意力，正确处理文档边界、位置和 EOS，避免把独立任务串成错误上下文。

**追问：** 为什么不能直接按 token ID 屏蔽全部 pad token？若 pad 与 EOS 共用 ID，可能误屏蔽真实 EOS；应结合原始长度、位置和模板生成标签。忽略标签语义见 [CrossEntropyLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)。

<a id="s03"></a>
### S03｜LoRA 的原理、参数量和合并条件是什么？【P0】

**回答要点：** 对冻结矩阵 $W\in\mathbb R^{d_{out}\times d_{in}}$，令：

$$
W'=W+\frac{\alpha}{r}BA,\quad
A\in\mathbb R^{r\times d_{in}},\quad B\in\mathbb R^{d_{out}\times r}.
$$

新增参数量为 $r(d_{in}+d_{out})$，而非 $d_{in}d_{out}$。常见初始化让一侧为零，确保初始增量为零且仍有一侧可接收梯度；两侧都零会阻断该路径的起始学习。标准线性 LoRA 可在部署时合并到兼容精度的基座权重。见 [LoRA 原论文](https://arxiv.org/abs/2106.09685)。

**追问：** rank 越大越好吗？更大 rank 增加容量和训练开销，效果还依赖目标层、数据量及正则化，应做同预算消融。

<a id="s04"></a>
### S04｜QLoRA 是否把所有训练计算都变成 4 bit？【P0】

**回答要点：** 不是。它以低比特形式存储冻结的基座，计算时按实现反量化到计算精度，训练 LoRA 等可训练参数。原论文还使用 NF4、双重量化和分页优化器降低存储及峰值开销。基座冻结仍需通过计算图传递梯度，激活显存不会因此消失。见 [QLoRA 原论文](https://arxiv.org/abs/2305.14314)。

**追问：** 能否直接把适配器合并进整数权重？通常要处理反量化、合并和重新量化，量化误差与后端支持需要单独验证。

<a id="s05"></a>
### S05｜如何设计一轮有结论的微调实验？【P0】

**回答要点：** 固定基座、模板、验证集和生成配置，记录数据版本、有效 token 数与预算。先验证小样本能否拟合，再比较不训练基线、清洗前后数据、目标层、rank、学习率和训练长度。每次优先改变一个因素，并同时评估目标任务、通用能力与成本。

**追问：** 只报告训练 loss 是否足够？不够。损失会受样本长度和掩码影响，必须报告真实任务指标、错误类别与方差或重复实验结果。

<a id="s06"></a>
### S06｜微调后答非所问或通用能力下降，如何定位？【P0】

**回答要点：** 先排查加载错基座、漏载适配器、chat template 不一致、EOS 与标签错位。若实现正确，再检查过拟合、数据偏置、学习率过大和灾难性遗忘。通过减少训练强度、混入通用数据或改善样本覆盖进行对照验证，不要在评测集上反复挑选提示词。

**追问：** 为什么高质量少量数据可能更有效？重复、错误或互相矛盾的大量样本会提供偏置信号；但“少量更好”仍是依赖任务和覆盖率的经验判断。

## 易错点

- 认为 LoRA 冻结基座就无需存储基座或中间激活。
- 将更低精度的权重存储等同于全部算子的计算精度。
- 训练和推理使用不同模板，却把退化归因于模型容量。
