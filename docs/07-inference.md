# 07 推理优化与部署

[返回首页](../README.md) · [题目索引](question-bank.md)

## 核心知识

推理要同时看首 token 延迟 TTFT、逐 token 延迟 ITL、端到端延迟、吞吐和服务目标内的有效吞吐。报告输入输出长度分布、到达率、并发、硬件和精度，才有可比性。

对所有层 KV 维度相同、无缓存分片或压缩的 Decoder，缓存估算为：

$$
M_{KV}=2LBSH_{kv}d_hb.
$$

$L$ 为层数，$B$ 为同时缓存的序列数，$S$ 为每条已缓存长度，$H_{kv}$ 为 KV 头数，$d_h$ 为单头维度，$b$ 为每元素字节。变长时将 $BS$ 替换为各序列缓存长度之和。

## 常见面试题

<a id="i01"></a>
### I01｜Prefill 和 Decode 的瓶颈有什么区别？【P0】

**回答要点：** Prefill 同时处理已知输入 token，矩阵计算并行度较高；Decode 每步为每条序列生成一个新 token，需要反复读取权重及历史 KV。在小批量常见配置下，前者更偏算力瓶颈，后者更偏带宽或访存瓶颈，但上下文、批量和硬件会改变结论。

**追问：** 为什么长请求影响短请求？长 prefill 会占用计算资源，长 decode 会占用缓存与调度槽位；chunked prefill、调度优先级或 prefill/decode 分离可缓解，但有额外开销。

<a id="i02"></a>
### I02｜算一次 GQA 的 KV Cache 显存需要哪些条件？【P0】

**回答要点：** 假设 $L=32$、$B=1$、$S=4096$、$H_{kv}=8$、$d_h=128$，BF16 每元素 2 bytes，则 $M_{KV}=536{,}870{,}912$ bytes，即 **512 MiB**。这不含权重、工作区、页表、碎片和预留容量；若是 KV 头数为 32 的 MHA，同条件下为 2 GiB。

**追问：** 使用 KV Cache 后注意力变为常数复杂度吗？不是。每个新 query 仍需读取并关注历史 key/value，标准全注意力单步开销随缓存长度增长。

<a id="i03"></a>
### I03｜FlashAttention 和 PagedAttention 分别解决什么问题？【P0】

**回答要点：** FlashAttention 通过分块与在线 Softmax 等方法减少 HBM 和片上存储间的数据搬运，避免完整物化注意力矩阵；它计算的是精确注意力，浮点结果不保证逐位相同。PagedAttention 以分块映射管理 KV 存储，减少碎片和冗余复制，有利于动态请求服务。二者关注点不同，可以结合。

资料：[FlashAttention](https://arxiv.org/abs/2205.14135)、[PagedAttention](https://arxiv.org/abs/2309.06180)。

**追问：** FlashAttention 把稠密注意力的计算复杂度变成线性了吗？没有，主要优化 IO 和中间存储，标准全注意力的二次计算关系仍存在。

<a id="i04"></a>
### I04｜INT8、INT4 量化如何影响速度与质量？【P1】

**回答要点：** 先区分权重量化、激活量化和 KV 量化，再说明 per-tensor、per-channel、分组、scale 和零点。量化降低存储与带宽，但加速依赖算子、硬件和反量化开销。校准集应覆盖实际任务、长度与异常值，分别评估准确性、首 token 延迟、逐 token 延迟和峰值显存。

**追问：** 7B 权重 INT4 为什么不只是 3.5 GB？3.5 GB 只是假设所有参数每个恰好 4 bit 的原始载荷；还需 scale、未量化层、对齐及其他元数据。方法实例见 [GPTQ](https://arxiv.org/abs/2210.17323) 与 [AWQ](https://arxiv.org/abs/2306.00978)。

<a id="i05"></a>
### I05｜温度、Top-k、Top-p、贪心和 Beam Search 如何比较？【P0】

**回答要点：** 温度调整分布锐度；Top-k 保留概率最大的固定数量候选；Top-p 保留累计概率达到阈值的最小候选集合，通常包含跨过阈值的 token，再归一化采样。贪心每步选最大概率，Beam Search 维护多个部分序列。高序列概率不保证事实正确或回答多样性。

**追问：** 如何保证 JSON 合法？结构化约束或语法约束可控制语法，还需要 schema、字段语义及业务规则验证；降低温度本身不能保证合法性。采样背景见 [The Curious Case of Neural Text Degeneration](https://arxiv.org/abs/1904.09751)。

<a id="i06"></a>
### I06｜连续批处理、前缀缓存和推测解码如何取舍？【P1】

**回答要点：** 连续批处理在生成步之间加入和移出请求，提高设备利用率；前缀缓存复用完全兼容前缀的 KV，需考虑模型、适配器、位置、租户与淘汰策略；推测解码用草稿模型提出候选并由目标模型验证，收益依赖接受率和验证成本。某些精确采样算法可保持目标分布，但不是任意接受规则都能保证。见 [Speculative Decoding](https://arxiv.org/abs/2211.17192)。

**追问：** 高 tokens/s 就意味着用户体验好吗？不一定。队列等待和尾延迟可能恶化，应在目标 SLA 下比较有效吞吐，而不是只追求离线吞吐峰值。

## 易错点

- 把平均 ITL 与每个间隔的 P95 当作同一个统计量。
- 用权重体积估算全部推理显存，不计 KV 与工作区。
- 将论文在特定负载的加速倍数当作任何环境的保证。
