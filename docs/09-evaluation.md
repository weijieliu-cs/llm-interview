# 09 评测与可靠性

[返回首页](../README.md) · [题目索引](question-bank.md)

## 核心知识

评测先回答三个问题：目标用户任务是什么，什么结果算成功，哪些失败必须单独统计。数据、提示词、模型和评分器都要版本化；固定测试集不应成为反复调参的开发集。

| 层次 | 示例指标 | 需要澄清的口径 |
| --- | --- | --- |
| 检索 | Recall@k、Hit@k、MRR@k、nDCG@k | 文档还是 chunk、重复 ID、相关标签 |
| 回答 | 正确性、证据忠实度、引用支持率 | 每条答案还是每个事实陈述 |
| Agent | 任务成功率、有效工具调用、执行成本 | 环境初始状态、部分成功、失败重试 |
| 服务 | TTFT、ITL、P95 延迟、SLA 内吞吐 | 长度分布、并发、排队与超时 |

多维评测思路参见 [HELM](https://arxiv.org/abs/2211.09110)。

## 常见面试题

<a id="e01"></a>
### E01｜如何构造可信的业务评测集？【P0】

**回答要点：** 从真实任务分布抽样，包含高频请求、困难样本、无答案、歧义、时效和权限场景。标注答案及可接受变体、证据、失败类型，检查标注一致性。按用户、文档簇或时间划分，防止近重复泄漏，保留独立最终测试集。

**追问：** 只用模型生成题目有什么风险？题目可能偏向该模型擅长的风格，存在可回答性与答案错误，需要人工抽查和真实请求校准。

<a id="e02"></a>
### E02｜Recall@k、MRR 和 nDCG 分别衡量什么？【P0】

**回答要点：** 对相关集合 $G$ 与前 k 个检索结果的去重集合 $R_k$，$\mathrm{Recall@k}=|G\cap R_k|/|G|$；Hit@k 只看是否至少命中一个。MRR 对各问题首个相关结果的倒数排名求平均，无命中记 0；若只看前 k 项，应写 MRR@k。nDCG 用理想排序归一化折损累计增益，适合分级相关性。

$$
\mathrm{DCG@k}=\sum_{i=1}^{k}\frac{2^{rel_i}-1}{\log_2(i+1)},\qquad
\mathrm{nDCG@k}=\frac{\mathrm{DCG@k}}{\mathrm{IDCG@k}}.
$$

**追问：** 没有相关答案的 query 怎么处理？召回率分母为零，需另定义无答案评测或明确跳过/置零。仓库的 [代码练习](../examples/README.md) 显式选择置零，并保留重复结果所占排名。

<a id="e03"></a>
### E03｜BLEU、ROUGE、LLM-as-a-Judge 能否替代人工判断？【P0】

**回答要点：** 字面重合指标适合特定任务，但对等价表达、事实错误和复杂指令的区分能力有限。模型评分器更灵活，也可能存在顺序、长度、自偏好和提示注入偏差。采用明确 rubric、打乱候选顺序、隐藏模型身份、多次评分及人工校准，并报告分歧。见 [MT-Bench 与 Chatbot Arena 的评审研究](https://arxiv.org/abs/2306.05685)。

**追问：** 评分器版本变了怎么办？重新标定或在重叠样本上做桥接评测，不能直接把新旧评分当作同一量尺。

<a id="e04"></a>
### E04｜pass@k 与单次准确率怎么比较？【P1】

**回答要点：** 单次准确率对应一个候选的成功率；pass@k 对应 k 个候选中至少一个通过判定。若某题采样 $n$ 个候选，其中 $c$ 个正确，常见估计为 $1-\binom{n-c}{k}/\binom nk$，要求 $n\ge k$，当 $n-c<k$ 时失败项为零。必须报告采样配置、测试用例和预算。见 [HumanEval](https://arxiv.org/abs/2107.03374)。

**追问：** 为什么不能拿一个系统的 pass@10 与另一个的单次准确率直接声称胜出？它们使用不同候选预算，也可能没有实际可用的正确答案选择器。

<a id="e05"></a>
### E05｜如何判断离线提升是否可信、能否上线？【P0】

**回答要点：** 在同一测试样本上做成对比较，按任务或用户簇估计不确定性，检查子集退化与多重试验挑选偏差。上线先小流量、明确成功指标与保护指标，并设定停止和回滚条件。离线分数提升不保证在线满意度或成本改善。

**追问：** 0.5 个百分点提升是否显著？取决于样本量、成对差异、相关性和方差；不能脱离误差范围回答。随机化应按可能相互影响的用户或会话层级设计。

<a id="e06"></a>
### E06｜怎样评估幻觉、拒答与信息泄漏？【P0】

**回答要点：** 将错误事实、证据不支持、错误引用、不该拒答却拒答、无依据仍作答及越权泄漏分开统计。构造有答案与无答案、正当与越权请求的配对测试，检查引用是否支持具体陈述，并在多轮与工具场景下复测。只降低回答率可能让幻觉率看似改善，需同时报告覆盖率或任务成功率。

**追问：** 模型自己说“置信度 95%”可信吗？未经校准的自然语言自信表达不是可靠概率，需要用可观测结果校准并评估选择性回答的风险与覆盖关系。

## 易错点

- 把 Hit@k 写成多相关文档场景的 Recall@k。
- 给多个副本或重复 chunk 重复计分，让评测虚高。
- 在测试集上反复调提示词，再把最优结果当作独立验证。
