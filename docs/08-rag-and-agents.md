# 08 RAG 与 Agent

[返回首页](../README.md) · [题目索引](question-bank.md)

## 核心知识

RAG 在生成前取得外部证据，Agent 则可能根据状态循环选择工具或行动。两者都需要明确数据、权限、失败处理和评测对象。

```mermaid
flowchart LR
    A[文档解析与版本管理] --> B[切分与索引]
    C[问题与用户权限] --> D[查询处理]
    B --> E[检索与过滤]
    D --> E
    E --> F[重排与上下文构造]
    F --> G[生成与引用]
    G --> H[验证与错误归因]
    H -.反馈.-> B
```

原始 RAG 工作见 [Retrieval-Augmented Generation](https://arxiv.org/abs/2005.11401)；实际企业流程通常还会增加权限、混合检索和重排等组件。

## 常见面试题

<a id="r01"></a>
### R01｜什么时候用 RAG，什么时候用微调？【P0】

**回答要点：** RAG 更适合动态事实、需要出处与访问控制的知识，微调更适合学习任务流程、格式和表达行为。两者可以结合：检索提供证据，微调提高利用证据的能力。选择应基于错误归因和成本，而非假定某种方案能解决所有幻觉。

**追问：** 上下文窗口足够大，为什么还要检索？文档筛选、权限、更新成本、噪声和输入费用仍然存在，应与全量长上下文方案做同任务比较。

<a id="r02"></a>
### R02｜如何设计文档切分和索引？【P0】

**回答要点：** 先正确解析标题、段落、列表、表格和代码，再按语义及结构切分。为 chunk 保留文档 ID、版本、位置、标题路径与权限元数据；选择 chunk 大小和 overlap 时同时看证据覆盖、噪声及 token 成本。索引应支持增量更新、删除传播和失败重试。

**追问：** overlap 越大越好吗？会提高跨边界证据覆盖，也会产生冗余、索引膨胀和评测重复命中，需要去重并按文档或证据单元明确指标。

<a id="r03"></a>
### R03｜为什么组合稀疏检索、稠密检索和重排？【P0】

**回答要点：** 稀疏检索如 BM25 对实体、编号和精确词项有优势；稠密检索捕获语义近似；重排模型用更细粒度的交互给候选排序，但成本更高。混合检索可用排名融合避免直接相加不同分数尺度，再用重排控制进入生成上下文的候选。

**追问：** 向量余弦相似度一定等于相关概率吗？不是。分数依赖嵌入模型、归一化和语料，阈值必须在具体分布上校准。稠密检索背景见 [DPR](https://arxiv.org/abs/2004.04906)。

<a id="r04"></a>
### R04｜RAG 答错时如何判断是哪一环的问题？【P0】

**回答要点：** 顺序检查原文是否存在答案、解析是否完整、候选是否召回、重排是否保留证据、上下文是否截断、生成是否忠实。把正确证据直接提供给生成模型做 oracle-context 对照：仍答错说明至少存在证据使用或生成问题。每层使用独立指标，不只看最终总分。

**追问：** 增大 Top-k 一定更好吗？召回可能提高，但噪声、重复、延迟和上下文成本也上升，应比较端到端质量与预算曲线。

<a id="r05"></a>
### R05｜什么任务值得使用 Agent？【P1】

**回答要点：** 当任务需要根据中间结果动态选择步骤和工具时，可考虑带状态的 Agent；固定流程任务通常先建立可观测的工作流基线。循环应包含状态、工具 schema、执行器、结果校验、终止条件以及调用和 token 预算。ReAct 展示了交替推理与行动的范式，见 [ReAct](https://arxiv.org/abs/2210.03629)。

**追问：** 如何避免循环和重复操作？设置最大步数、检测重复状态、为写操作使用幂等键，区分可重试失败与必须交由用户处理的失败。

<a id="r06"></a>
### R06｜如何处理 RAG 和工具调用中的权限与提示注入？【P0】

**回答要点：** 把检索文档和工具输出视为数据，不能让其中的指令改变系统权限。检索时过滤授权范围，工具执行前在服务端重新校验身份、资源和参数；对有副作用的操作设置符合业务要求的确认与审计。引用文档也不等于证明生成陈述被该文档支持。

**追问：** 把权限要求写进提示词就够了吗？不够。权限必须由模型外的确定性逻辑强制执行，缓存和索引也需要租户隔离。风险分类见 [OWASP LLM 应用风险项目](https://owasp.org/www-project-top-10-for-large-language-model-applications/)。

## 易错点

- 文档级权限控制只放在生成后过滤，召回阶段已泄漏证据。
- chunk 编号变化后继续复用旧评测标签。
- 只记录最终答案，不保留检索候选、重排结果和工具错误。
