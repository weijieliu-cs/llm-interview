# 10 系统设计与场景题

[返回首页](../README.md) · [题目索引](question-bank.md)

## 回答框架

按“需求和约束 → 基线 → 数据及架构 → 容量与成本 → 评测 → 失败处理”组织回答。先说明假设再做估算；没有输入输出长度、到达率、硬件与 SLA 时，不给出看似精确的机器数量。

## 常见面试题

<a id="x01"></a>
### X01｜如何设计一个企业内部知识库问答系统？【P0】

**回答要点：** 先确认文档规模、格式、更新频率、用户权限和引用要求。建立解析及版本流程，使用带权限元数据的索引、混合检索、重排与证据生成。给出无答案、冲突文档和索引失败的处理方式，分层测召回、回答正确性、引用支持率、越权率与延迟。将“提示词直答”和“基础 RAG”作为可比较基线。

**追问：** 删除敏感文档后如何保证不再出现？传播到原文、索引、缓存及引用层，记录删除版本和审计结果，必要时使缓存立即失效；不能只等待周期性重建。

<a id="x02"></a>
### X02｜一张 24 GiB GPU 上如何做 7B 模型微调？【P0】

**回答要点：** 先看结构、序列长度、训练目标和精度。全参 Adam 模型状态通常远超预算，可以评估 LoRA 或 QLoRA，结合小 microbatch、累积和激活重计算。先在目标长度跑一个训练 step 测峰值，再扩大到验证负载。7B 的 4 bit 原始权重约 3.5 GB，但额外状态和激活会明显增加占用，不能据此保证任何任务都能跑。

**追问：** 上下文翻倍为何可能 OOM？激活与注意力中间量随长度增长，是否物化分数矩阵和是否重计算都会影响增长形式。

<a id="x03"></a>
### X03｜要求 100 QPS 的模型服务需要多少 GPU？【P0】

**回答要点：** 先补全输入输出长度分布、到达模式、TTFT/ITL SLA、模型精度和硬件。按实际负载压测单实例在 SLA 内可持续处理的请求率，再估算副本数，加入峰值、故障冗余和流量偏斜。输入 token 速率约为 $\lambda E[S_{in}]$，输出约为 $\lambda E[S_{out}]$；二者只是负载描述，不能直接替代 prefill/decode 混合压测。

**追问：** 如何估计平均在途请求？稳定系统中 Little 定律给出 $\bar N=\lambda\bar W$；其中 $\bar W$ 为平均端到端时间，不能用 P95 代替均值并声称精确关系。缓存容量还要考虑长度与并发的联合分布。

<a id="x04"></a>
### X04｜上线后正确率下降且 P95 延迟升高，怎么处理？【P0】

**回答要点：** 先核对影响范围、发布版本和保护指标，必要时按既定策略回滚或降级。对比请求长度、语言、领域、检索命中率、工具错误和排队时间，区分模型退化、索引版本、流量变化及资源瓶颈。保存可脱敏重放的失败样本，再用最小变更验证根因。

**追问：** 只能先修一个问题时如何决策？根据用户影响、越权风险、错误扩散和恢复成本排序，并保留后续诊断证据；不是直接调大所有超时。

<a id="x05"></a>
### X05｜如何证明微调或 RAG 改动的收益来自关键设计？【P0】

**回答要点：** 固定数据划分、基座、提示词、生成配置和预算，设置不训练或基础检索基线，再对目标组件做消融。联合比较质量、延迟和成本，报告错误类型、重复实验或置信区间。若同时换了数据、模型和重排器，只能说明组合效果，无法单独归因。

**追问：** 某组件提高离线分数但显著变慢，如何决策？给出预算约束下的效果曲线，可按问题难度路由、缩小候选或缓存，并用线上指标验证最终收益。

<a id="x06"></a>
### X06｜如何向面试官讲清楚一个真实项目？【P0】

**回答要点：** 用一分钟说明问题、个人职责、数据规模、基线、关键改动、实际结果和限制。选一个失败案例解释诊断过程，再用消融或日志支撑设计选择。不要把团队整体成果全部归为个人工作；未知数字应明确缺失，而不是编造。

**追问：** 如果重做会改什么？结合已知瓶颈给出优先级、预期验证和止损标准。可使用 [项目与模拟面试模板](interview-practice.md)。

## 易错点

- 先报框架名称，再倒推一个并不存在的需求。
- 未压测就按峰值 FLOPs 直接换算线上 QPS。
- 只展示成功路径，不说明失败回退、监控或数据更新。
